# 后续待办（Backlog）

> 建立于 2026-09-19。本文件只放**未排期的中长期方向**：已定案的做法在 `AGENTS.md`
> 「已定案」，正在做与做完的在 `PROGRESS.md`，这里记录「将来要做、但还没轮到」的事。
> 每条只写清**目标 / 现状 / 待定问题**，不写实现方案（轮到做时再按歧义处理规则商讨定案）。

## 1. 提供商与 LLM 协议更新与优化

- 现状：`core/llm` 已有多提供方抽象 + fallback + 双传输（openai SDK / httpx 手写）+
  流式 + 原生 tool_calls；`providers.toml` 管理模型元数据，`aris llm fetch` 做 /models 同步。
- 目标：跟上上游协议变化（新 API 形态、新字段、新提供方），并优化现有链路
  （重试/超时预算、流式分片拼装、token 统计、错误信息质量）。
- 待定：具体要接哪些提供方与协议版本，轮到做时再评估。
- 参考：`developDoc/LLM-PROVIDER-MGMT.md`、`developDoc/API-CALL.md`。

## 2. Skills 迁移至 `data/`

- 现状：技能目录固定在包内 `src/aris/behavior/skills/`（`SKILLS_DIR`），
  改一个 skill 就要动仓库；WebUI 技能管理页也指向包内目录。
- 目标：技能落到运行时目录 `data/skills/`（不进 git、可随时热改），
  包内只留少量内置 skill 作初始种子。
- 待定：内置 skill 与用户 skill 的**优先级与覆盖规则**、首次启动是否自动播种、
  WebUI 技能页如何切换目标目录、已有 skill 的迁移动作。
- 参考：`developDoc/SKILLS.md`。

## 3. 开放各模块对外接口（面向插件系统）

- 现状：CMCB 只有**进程内**服务注册表（`core.provide` / `core.call`），
  没有对外的稳定契约；插件系统仍为草案，无代码。
- 目标：为插件 / MCP / 第三方定义稳定的对外接口——能力声明、服务发现、
  版本标记、生命周期钩子。CMCB 正好是现成底座，但「对内总线」与「对外契约」
  是否同一套机制需要定案（隔离、权限、崩溃不拖垮主进程等）。
- 参考：`developDoc/PLUGIN.md`（草案，多处 `[待讨论]`）。
- 相关（2026-09-19）：`aris serve` 启动编排已定案（`developDoc/SERVE.md`）——它是
  **组装根**，只管把模块按序拉起来；**对外契约仍归 CMCB**，两者不重叠。

## 4. 多人格与多人格共同运行

- 现状：`persona/` 只有一个 `persona.system_prompt` 服务，提示词工程起步版，
  单人格全局唯一。
- 目标：人格可定义、可选择、可持久化；**多个人格同时运行**（各自会话状态、
  各自上下文），并明确人格之间共享什么（记忆？知识库？工具？）。
- 待定：多人格的运行形态（多进程 / 多会话 / 多实例）、人格隔离边界、
  与记忆系统（#5）的归属关系。
- **前置未定（2026-09-19 决定先置着）**：人格载体（`data/personas/<id>/` 文件
  vs PG 表）与对话历史（会话是否落 PG）。做本项前**必须先定**，否则表结构返工；
  详见 `AGENTS.md`「待定」。
- 参考：`AGENTS.md`「待定」节的人格系统条目。

## 5. 上下文压缩（属记忆系统）

- 现状：无压缩，长对话直接顶上下文上限（`providers.toml` 的 `context_length`
  只作元数据，未参与决策）。
- 目标：滚动摘要 + 关键信息抽取入记忆，长会话不丢要点、不爆上下文。
- 归属：`memory/` 模块（复用 `store/`），与三层记忆模型（感觉/短期/长期）
  一起设计，不单独造轮子。
- 参考：`AGENTS.md`「待定」节的记忆架构条目。

## 6. 多模态模型支持

- 现状：`LLMModel.capabilities` 已有 `vision` 标志位，但消息结构、工具返回、
  存储、WebUI 都只处理文本。
- 目标：打通图像等模态的输入（消息内容块 / 上传）、能力探测与降级、
  以及必要时的多模态输出（语音另有 `voice/` 主线）。
- 待定：先做哪条链路（对话贴图 / 知识库图片资料 / 截图理解）。

## 7. 自动任务与基于自动任务的主动操作

- 现状：一切由用户输入驱动，无调度器、无后台触发，Aris 不会自己发起动作。
- 目标：定时任务 + 事件触发（新消息、新资料入库、记忆到点等），
  Aris 可**主动**做事（发消息、查库、写记忆、推进长期目标）。
- 待定（关键）：主动操作的**边界与频率**（不打扰用户）、失败兜底、
  是否需要「目标/计划」这一层状态（与 #4 多人格、#5 记忆都有耦合）。
- 依赖：#3（对外接口）与 #5（记忆）落地后做更自然。

## 依赖关系速查

- `store/` 已就位 → #5 可以开工；#4 与 #5 相互耦合（人格要各自的记忆视图）。
- #3 是插件系统、多人格、自动任务共同的底座，越早定契约越省返工。
- #2 独立、改动小，可随时插队。
- #1、#6、#7 与主线相对独立，按外部需要驱动。
